## ١. لماذا هذه الميزة (المشكلة الحقيقية)

الوضع اليوم ليس «ناقص ميزة» بل **قاعدة ملزمة غير منفَّذة** وثغرة رقابية:

| # | النتيجة الفعلية | الدليل من الكود |
|---|---|---|
| ١ | **«الإدارة» نص حر** يكتبه المستخدم، فـ«المالية» و«الادارة المالية» إدارتان مختلفتان في التقارير | `competitions.requesting_department` و`supervising_department` و`annual_plan_items.department` كلها `varchar` |
| ٢ | **الحقل مهمَل عمليًا** — ٨٨ من ٩٠ عقدًا على staging بلا إدارة | استعلام مباشر على قاعدة البيانات |
| ٣ | 🔴 **أي مستخدم يملك `competitions.approve` يعتمد كل خطوات السلسلة** (المالية، الإدارة العليا، CDM) | `DecideCompetitionApprovalUseCase` يستقبل `actorId` فقط ولا يتحقق من دور الخطوة |
| ٤ | **R‑04 غير منفَّذة** — نصها: «لـCDM وصول دائم على **طلبات إدارته**» | `RULES.md §R‑04`؛ لا يوجد كيان إدارة أصلًا |
| ٥ | **الإشعار للإدارة المشرفة يعتمد على إيميل يُكتب يدويًا** لكل عقد | `notify_supervising_department` + `supervising_department_email` |
| ٦ | **اللجان غير مُنمذجة نهائيًا** رغم ١٩ صلاحية لجان في المصفوفة | لا يوجد كيان لجنة؛ فقط `evaluatorId` و`committee_memo_number` |
| ٧ | **القيمة التقديرية مكشوفة للجميع** رغم أنها «مظروف سري» نظامًا | `estimated_value` يظهر لأي حامل `competitions.read` |

**فرصة معمارية:** سباكة النطاق (`OrgScope` / `orgWhere`) ما زالت مثبتة في **١٠ مستودعات** ومعطّلة
بعد إلغاء تعدد الجهات — يمكن **إعادة استخدامها** لنطاق الإدارات بدل بناء تصفية جديدة.

## ٢. الفرق الجوهري: إدارة ≠ لجنة

| | **الإدارة** | **اللجنة / الفريق** |
|---|---|---|
| العمر | دائمة | مؤقتة (بقرار تشكيل ومدة) |
| العضوية | المستخدم في إدارة واحدة | عضو في عدة لجان معًا |
| التركيب | من داخل الإدارة | **عابرة للإدارات** |
| الأدوار | مدير / نائب / عضو | رئيس / **نائب رئيس** / عضو / **عضو احتياطي** / سكرتير |
| القرار | فردي (المدير يعتمد) | **جماعي بنصاب** |
| المخرج | اعتماد أو رفض | **محضر توصية** → يعتمده صاحب الصلاحية |
| النطاق | ملكية وتوجيه وتصفية | تقييم وتوصية موثّقة |

> **قرار تصميمي:** كيانان منفصلان تمامًا، والعلاقة بينهما: عضو اللجنة **يأتي من** إدارة
> (تُحفظ إدارته وقت العضوية كلقطة).

## ٣. النموذج المقترح

### ٣‑١ الإدارات

```
departments
  id, code, name, parent_id (شجرة مفتوحة العمق), type,
  manager_user_id, deputy_user_id, email, approval_ceiling (nullable),
  status (active|archived), created_at, updated_at

department_members
  id, department_id, user_id, role (manager|deputy|member),
  active_from, active_to (null = حالي)
```

**`type`** هو ما يربط الإدارة بخطوة الاعتماد (بدل الأدوار الوهمية الحالية):
`requesting` · `procurement` · `contracts_cdm` · `finance` · `budget` · `legal` ·
`higher_management` · `pmo` · `cyber` · `local_content` · `warehouse`

### ٣‑٢ صاحب الصلاحية والعتبات

```
approval_authorities
  id, level (رقم الترتيب), title (مدير عام / نائب الرئيس / صاحب الصلاحية),
  department_id (nullable), user_id (nullable),
  min_amount, max_amount
```

سلسلة RGA المرجعية: `إدارة طالبة → أخصائي → مدير الإدارة → مدير عام الإدارة العامة
للمشتريات → نائب الرئيس التنفيذي → صاحب الصلاحية` — **تُشتق من شجرة الإدارات + العتبة المالية**.

### ٣‑٣ اللجان

```
committees
  id, code, name, type, scope (standing|per_competition),
  formation_ref, formation_date, term_ends_at,
  quorum_min, etimad_name (للمطابقة مع قوائم اعتماد),
  status, created_at

committee_members
  id, committee_id, user_id,
  role (chair|deputy_chair|member|alternate|secretary),
  department_id_snapshot, coi_declared_at, active_from, active_to

committee_minutes                      -- المحاضر والتوصيات
  id, committee_id, subject_type (competition|contract), subject_id,
  kind (opening|technical|examination|qualification|recommendation|specialized),
  decision, recommendation_text, quorum_met (bool),
  members_snapshot (jsonb — من كان عضوًا وقتها),
  file_id (المحضر الموقّع), signed_at, created_by, created_at
```

**أنواع اللجان:** تأهيل · فتح عروض · فنية · فحص عروض · شراء مباشر · مزايدة عكسية ·
**اللجنة المختصة** (بنود غير مماثلة/تمديد/إنهاء/سحب/تنازل) · استلام موقع · استثناء ·
**خارجية** (الرأسمالية بوزارة المالية · التظلمات · مخالفات المتنافسين).

### ٣‑٤ السرية (المظروف السري)

القيمة التقديرية دور مستقل نظامًا («مُدخل التكلفة التقديرية»):
- صلاحية جديدة `competitions.estimated_value.read`
- حقل `estimated_value_sealed_until` (تُفتح تلقائيًا بعد فتح العروض)
- كل اطلاع يُسجَّل في التدقيق

## ٥. خطة التنفيذ

### M0 — القرارات والمُدخلات (بانتظار المختصين)
- إجابات الأسئلة الحاسمة أعلاه.
- **الهيكل الإداري الرسمي**: أسماء وأكواد الإدارات والأقسام ومديروها وإيميلاتها.
- **قائمة اللجان** وقرارات تشكيلها وأعضاؤها.
- **جدول العتبات المالية** (من يعتمد حتى أي مبلغ).

### M1 — سجل الإدارات والعضوية
- كيان `departments` + `department_members` + هجرة قاعدة البيانات.
- صلاحيات: `departments.read` / `departments.manage`.
- واجهة: صفحة الإدارات (شجرة + إنشاء/تعديل/أرشفة)، تعيين المدير والنائب والأعضاء.
- استبدال حقول النص الحر بقوائم منسدلة (المنافسات، العقود، بنود الخطة) مع الإبقاء
  على النص القديم كلقطة.
- **معيار القبول:** إنشاء شجرة إدارات كاملة، وإسناد كل مستخدم لإدارته، وظهور اسم
  الإدارة الموحّد في التقارير.

### M2 — سلسلة الاعتماد الحقيقية
- `approval_authorities` (العتبات) + اشتقاق السلسلة من الشجرة.
- استبدال `ApprovalRole` الوهمية بربط فعلي: كل خطوة ← إدارة/منصب محدد.
- **سد الثغرة**: التحقق من أن المعتمِد صاحب الخطوة (مع فترة سماح تسجّل تحذيرًا أولًا).
- توجيه الإشعارات من `departments.email` بدل الإيميل اليدوي.
- **معيار القبول:** محاولة اعتماد خطوة لست صاحبها تُرفض (بعد فترة السماح) وتُسجَّل.

### M3 — النطاق والتصفية
- تحويل سيم `OrgScope` المعطّل إلى `DeptScope` عبر المستودعات العشرة.
- صلاحيات الرؤية الشاملة: `contracts.read.all` / `competitions.read.all` لـCDM والإدارة العليا.
- **معيار القبول:** موظف الإدارة الطالبة يرى طلبات إدارته فقط؛ CDM يرى الكل (R‑04).

### M4 — الإسناد (إكمال R‑04)
- إسناد الطلب لموظف داخل الإدارة، ونقل صلاحية *الإجراء* مع بقاء وصول CDM.

### M5 — اللجان والمحاضر
- `committees` + `committee_members` + `committee_minutes`.
- الأدوار الخمسة، النصاب، الإحلال عند الغياب.
- فحص العضوية ضد محرك فصل المهام + إقرار تعارض المصالح.
- لقطة العضوية مع كل محضر + رفع المحضر الموقّع.
- فصل التوصية عن الاعتماد.
- **معيار القبول:** تشكيل لجنة، تسجيل درجات الأعضاء، إصدار محضر توصية بنصاب صحيح،
  ثم اعتماد صاحب الصلاحية — كل ذلك موثّق في التدقيق.

### M6 — السرية والمدد
- المظروف السري للقيمة التقديرية (صلاحية + ختم زمني + تدقيق كل اطلاع).
- المدد المعيارية لكل إجراء/إدارة + تنبيهات التأخير + لوحة الالتزام.

> **الترتيب ليس صارمًا:** M6 (السرية) مستقلة تقنيًا ويمكن تقديمها لو اعتُبرت أولوية رقابية.

## ٦. المخاطر

| الخطر | التخفيف |
|---|---|
| **سد ثغرة الاعتماد يوقف العمل** إن لم تُضبط الإدارات أولًا | فترة سماح (تحذير في التدقيق دون منع) حتى اكتمال M1 |
| تعقيد الشجرة والعتبات يربك المستخدم | البدء بالافتراضيات، وإخفاء العتبات خلف إعدادات متقدمة |

| تغيير العضوية يفسد المحاضر القديمة | لقطة عضوية إلزامية مع كل محضر |
| عدم مطابقة أسماء اللجان لقوائم اعتماد | حقل `etimad_name` مخصص للمطابقة |

## ٨. ملحق — أسماء واقعية من دليل RGA

الرأسمالية (وزارة المالية).
